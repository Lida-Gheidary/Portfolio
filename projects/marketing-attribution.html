Exploring Marketing Attribution with Adobe CJA Demo Data

An exploratory analysis using Python and SQL to compare exported attribution results.

Read the full exploration Source files and code
01The question and the exports

A customer may encounter several marketing channels before placing an order. Attribution determines how a report shares credit between those interactions. I wanted to explore how the credit reported for each channel changes when the model or lookback window changes.

The project uses Adobe Customer Journey Analytics demo exports for May 1–31, 2026. The main report contains 16 channels and six attributed-order measures: last-touch, linear, and algorithmic results, each with a 14-day and a 30-day lookback. Adobe had already calculated these allocations. The exported rows are channel summaries, rather than complete customer journeys.

Why include additional exports?

The attribution report answers the main comparison question. Three supporting reports add other views of the same channels: acquisition and closure measures for a descriptive correlation, reported revenue for revenue-per-order comparisons, and conversion environments for the distribution of attributed orders across Website, Mobile App, Mobile Web, Point of Sale, and Call Center.

Four of the repository’s 13 raw CSV files feed the analysis. The remaining downloads are retained as supplementary material. The full exploration explains the contents and analytical purpose of each used export, with links to the files and a worked example of how to read a row.

02What Python and SQL contributed

In Python, I used pandas to remove export metadata from the channel rows, standardise the fields, check channel names and missing values, and join the four inputs. The resulting master table contains 16 channels and 26 fields. I calculated relative differences between exported model results, environment shares, reported revenue per attributed order, and descriptive correlations. Matplotlib produced the saved charts.

Each relative difference uses last-touch as its baseline within the same window: subtract last-touch credit from the alternative allocation, divide by last-touch credit, and multiply by 100. Keeping the window consistent makes the comparison explicit.

SQLite queried the prepared tables to rank credit changes, place the exported Lifecycle Index in numerical bands, join environment shares, and compare revenue with a median supplied by Python. SQL used the differences already calculated in Python. Neither tool rebuilt Adobe’s models.

The website’s figures and downloadable comparisons are generated from the analysis outputs. Source checks reconcile the allocations and environment counts, and the repository provides a command to rerun the complete workflow.

Implementation and AI assistance

I defined the questions, supplied the exports, ran proposed code in VS Code, and reviewed outputs through an iterative process. Claude Sonnet supported the initial implementation; ChatGPT supported subsequent review and revision. The code and checks make that workflow inspectable.

03Observations and their limits

Three observations show why the model, baseline, and window need to be stated alongside a channel’s reported result.

  • Paid Search changes direction across models. At 30 days, it receives 12.09% more algorithmic credit and 5.71% less linear credit than last-touch.
  • Email receives less credit but keeps its rank. Its algorithmic credit is 43.90% lower at 30 days, yet it ranks first by attributed orders under all six settings.
  • SMS shows the effect of the window on the comparison. Algorithmic credit is 7.10% lower than last-touch at 14 days and 17.47% lower at 30 days, using each window’s own baseline.

Model totals agree within each window, but the 30-day total is 4,505 higher than the 14-day total. The exports do not explain that gap, so an identical set of attributed orders cannot be assumed across windows.

The findings describe differences in assigned credit in one month of demo data. Missing journey records, incomplete metric definitions, and the absence of campaign costs or experiments prevent conclusions about causal contribution, profitability, or an optimal marketing budget. The project’s purpose is to make the reporting differences understandable and reproducible.
