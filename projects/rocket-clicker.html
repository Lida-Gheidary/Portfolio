01 Overview

Status: COMPLETE / DEPLOYED

PURPOSE: Practice JavaScript gameplay alongside connecting external services, sending API requests and handling shared data.

THE EXERCISE: Build a game where players click or tap rockets during a 60 second round, and connect it to the Google Sheets leaderboard provided by the class teacher.

TECHNOLOGY: HTML, CSS, JavaScript, Firebase and Webpack. Hosted on GitHub Pages, with deployment through GitHub Actions.

DATA: Player names and scores, initially sent to the class teacher's Google Sheets setup and later stored in my own Firebase Cloud Firestore database.

Round length 60 seconds

Score before the timer ends

Each rocket 1 point

Click or tap to score

Leaderboard Top 20

Shared scores from all players

Signup None

Anonymous Firebase authentication

02 What It Does

Status: COMPLETE

GAMEPLAY: Rockets appear at random positions. Each successful click or tap earns one point. Scoring stops when the timer reaches zero.

SUBMISSION: Players enter a name and save their score. Firebase identifies the player anonymously, without a signup form.

LEADERBOARD: The 20 highest scores appear in a popup automatically after submission. The newly saved entry is highlighted if it reaches the top 20.

INTERFACE: Orbitron typography, custom monochrome rockets and a responsive layout for desktop and mobile screens.

ERROR HANDLING: Failed submissions and leaderboard requests show a message with an option to retry.

03 How It Was Built

Status: AI ASSISTED / REVISED WITH FIREBASE

STARTING POINT: The project began with the class teacher's starter repository and was developed from there.

FIRST CONNECTION: The class teacher had prepared the Google Sheets leaderboard and supporting Zapier and API setup. I implemented the game's connection to those services, practising score submission and retrieval alongside the game code.

LATER REVISION: I replaced that connection with my own Firebase setup, redesigned the interface and added automatic leaderboard display.

AI ASSISTANCE: Initially developed using Claude Sonnet 5.5 in chat mode, then revised using ChatGPT 6.1 Sol in chat mode.

Iterative development

Describe → Generate → Run in browser → Review → Refine

I followed the same iterative approach as my other projects to practise applying, testing and refining code. Each version was run in the browser, reviewed against what it did and revised using that feedback.
